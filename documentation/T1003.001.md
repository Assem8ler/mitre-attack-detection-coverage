# T1003.001 — OS Credential Dumping: LSASS Memory

## Attacker behavior
Adversaries dump LSASS memory to steal credentials: comsvcs.dll MiniDump,
procdump, MiniDumpWriteDump, Out-Minidump, often wrapped in PowerShell.

## Telemetry
- PowerShell Script Block Logging (4104) for PowerShell-wrapped dumpers
- Follow-up: Sysmon EID 10 (ProcessAccess to lsass.exe) for native dumpers

## Detection logic
- No built-in rule covers comsvcs/MiniDump patterns (grep of ruleset: empty)
- BUT generic 4104 base rule 91815 matches every script block first
- rule 100501 (level 12): child of 91815 + pcre2 pattern
  (comsvcs.dll MiniDump | MiniDumpWriteDump | Out-Minidump | procdump lsass | lsass.dmp)

## Validation plan

| # | Test command | Expected alert | Result |
|---|--------------|----------------|--------|
| 1 | `powershell -c "rundll32 comsvcs.dll, MiniDump (Get-Process lsass).Id C:\temp\lsass.dmp full"` | 100501, level 12 | ✅ detected (both failed and successful dump attempts) |

## Lessons learned
- Generic 4104 base rule (91815) means standalone custom rules on script blocks
  can never win — child chaining is mandatory for PowerShell detections
- Detection fires on ATTEMPT: missing output directory did not prevent the alert
- XML hygiene: an unclosed tag in custom rules file crashes wazuh-manager
  (XMLERR line N); use full-file overwrite (heredoc) instead of partial nano edits
- Lab safety: real LSASS dump executed only in isolated VM, dump file removed after test
