# T1053.005 — Scheduled Task/Job: Scheduled Task

## Attacker behavior
Attackers create scheduled tasks for persistence and execution:
`schtasks /create`, `New-ScheduledTask`, often running powershell/cmd/mshta from task action.

## Telemetry
- Security Event ID 4698 (scheduled task created)
- Prerequisite: audit "Other Object Access Events" success enabled
  (on non-English Windows use secpol.msc or localized subcategory name)
- Security channel is collected by Wazuh agent by default — no agent changes needed

## Detection logic
- rule 100301 (level 6): child of built-in 60228 — any task creation (persistence installed)
- rule 100302 (level 10): child of 100301 — taskContent contains interpreter/download
  (powershell|cmd|wscript|cscript|mshta|curl.exe|bitsadmin|Invoke-WebRequest)
- Three-level chain: built-in 60228 -> 100301 -> 100302

## Validation plan

| # | Test command | Expected alert | Result |
|---|--------------|----------------|--------|
| 1 | `schtasks /create /tn LabPersistEvil /tr "powershell.exe -nop -w hidden ..." /sc onstart /f` | 100301 + 100302 | ✅ detected |
| 2 | `schtasks /create /tn LabPersistBenign /tr "notepad.exe" /sc onstart /f` | 100301 only | ✅ detected |

## Lessons learned
- FP lesson: bare "http" in taskContent matched the task XML xmlns schema URL; replaced with specific download primitives.
- Wazuh emits ONE alert per event (highest rule in chain): parent 100301 appears only for benign tasks, child 100302 for malicious ones — this is intended severity separation.
- Rules match only NEW events after deploy: always re-run tests post-restart.
